# atlas

Per-declaration records of what each constant of the pinned Mathlib
depends on: its axioms and tier, its kind and module, computability,
and how its name was made.  Once the translator exists, the records
grow to carry the kernel features a constant's typing used, the
universe-elaboration result, and its acceptance under each target
profile; issue M4-1 defines that schema in `SCHEMA.md`.

Issue M1-11 produced the first version (format version 0, axioms only)
with a Lean program in `../translator/` and a stdlib-only Python report
in `../scripts/python/`.  The report for the pinned revision is
committed under `../docs/reports/`; the record files are regenerable
and are not.

## Producing the records

`make atlas`, in the default shell, runs the following two steps:

1.  `lake exe atlas` in `../translator/`, which imports `Mathlib` from
    the `.olean` files of Mathlib's cache, computes the exact axiom set
    of every constant of the resulting environment, and writes the
    records;
2.  `scripts/python/atlas_report.py`, which reads them and writes the
    report and a table of tiers per module.

The program needs Mathlib's cache in `../translator/.lake/` (`make
lean-cache`), about 7.5 GiB of memory, and about three minutes.  It
writes the following files, named after the Mathlib tag and commit that
`../translator/lake-manifest.json` pins:

+  `mathlib-<tag>-<commit>.ndjson`: the records, 221 MB at v4.33.1;
+  `mathlib-<tag>-<commit>.run.json`: the run's time per phase and its
   peak memory;
+  `mathlib-<tag>-<commit>.modules.tsv`: the tiers of every Mathlib
   module, written by the report script;
+  `../docs/reports/atlas-mathlib-<tag>-<commit>.md`: the report, the
   one file of the four that is committed.

`lake exe atlas --import MODULE --out FILE.ndjson` writes the records
of a smaller environment, which is quicker to look at; `--import` may
be repeated.  `python3 scripts/python/atlas_report.py FILE.ndjson` then
reads `FILE.run.json` from beside it, writes `FILE.modules.tsv` there,
and writes its report to `docs/reports/atlas-FILE.md`, never over the
pin's.

At Mathlib v4.33.1 (commit `0df444a`) and Lean v4.33.1, the records
file was 221,461,382 bytes with SHA-256
`368acfe185c9fc58984e6f5ceadde62f35cec7148ce4f898baf05c22c1c057e8`, and
two runs wrote the same bytes.

## The records

Each line is one JSON object.  The first line is the header,
`{"atlas": {...}}`, with the format `version` (0), the `lean` version
and `lean_commit`, the `mathlib` tag and `mathlib_commit`, the
`imports`, and the number of `constants`.  The last line is
`{"end": {...}}`, with the number of `records` and, under
`value_graph`, the `population` and `classical` count of Mendoza-Smith's
method (below); a file without it was cut short, and the report refuses
it.

Between them is one line per constant of the environment, every
module's constants included, ordered by name as strings compared
character by character (UTF-8 byte order).  The fields, in the order
they are written, are as follows:

+  `name`: the constant's name as Lean prints it, with `«...»` around a
   component that is not an identifier, so that Lean can read it back;
+  `module`: the module that declares it;
+  `kind`: `axiom`, `definition`, `theorem`, `opaque`, `quotient`,
   `inductive`, `constructor` or `recursor`, after its `ConstantInfo`;
+  `axioms`: the axioms it depends on, sorted, exactly (below);
+  `tier`: `T0` to `T3`, from `axioms`, as `../corpus/SCHEMA.md`
   ("Tiers from axioms") computes it;
+  `lean_omits`: the part of `axioms` that `Lean.collectAxioms`, and so
   `#print axioms`, leaves out (below); empty for all but a few
   constants;
+  `noncomputable`: Lean's `isNoncomputable`, true of a declaration
   marked `noncomputable` and of one the compiler could not compile,
   which a `noncomputable section` allows without an error;
+  `unsafe`: the constant is `unsafe`;
+  `partial`: it is a `partial def`, an `opaque` constant with a
   companion definition `<name>._unsafe_rec`, whose safety is `partial`
   rather than `unsafe` (`partial` leaves no other trace; `#print axioms`
   shows nothing);
+  `private`: Lean's `isPrivateName`, a name beginning
   `_private.<module>.0.`;
+  `internal`: Lean's `Name.isInternal`, some component of the name
   begins with an underscore (`_private`, `_proof_1`);
+  `auto`: the constant is auto-generated by the test of Batteries'
   linters (`Lean.Environment.isAutoDecl`, which Mathlib's `#lint`
   runs), copied into `../translator/Atlas/AutoDecl.lean`.  It judges a
   private name by the name it was written with; Lean's own
   `isAutoDeclOrPrivate_Internal` is `auto` or `private`.

## How the axioms are computed

A constant depends on an axiom when the axiom is reachable from it
along the edges `Lean.collectAxioms` follows: from each constant to the
constants its type uses, to those its value uses (definitions,
theorems, opaque constants), and from an inductive type to its
constructors.  The program builds that graph once for the whole
environment and searches it backwards from each axiom
(`../translator/Atlas/Graph.lean`).

It does not take `Lean.collectAxioms`'s answer, because at Lean v4.33.1
that answer can be incomplete.  The function caches the result of a
constant it reaches while one of the constant's own dependencies is
still being visited, counting that dependency as having no axioms, and
each `.olean` stores the results for its declarations in a table that
importing modules trust (Lean issue [15226]).  The cycles where this
bites are an inductive type and its constructors, and mutually
recursive definitions such as the `_unsafe_rec` companions of mutual
`partial def`s.  The program still calls
`Lean.collectAxioms` on every constant, records what it leaves out in
`lean_omits`, and stops with an error if it ever names an axiom the
graph does not reach.  At v4.33.1 it under-reports 1,837 constants of
the environment, 550 of them Mathlib's, and over-reports none.

Mendoza-Smith's method, whose two numbers the last line carries, takes
a narrower graph: its nodes are the constants whose names are not
internal, and its edges run from a definition's or theorem's value,
without its type, to the non-internal constants the value uses.  A node
is classical when `Classical.choice` is reachable from it.  The report
compares both computations with the published counts.

## Probes

`probes/` holds standalone Lean files that measure a Mathlib checkout
at any revision, where the atlas program, built against the pinned
Lean, cannot run.  Each imports only Mathlib and Lean's core and is run
from the checkout, under the Lean its `lean-toolchain` names, with
`lake env lean /path/to/atlas/probes/<file>.lean`; each counts the
constants the imports declare, never its own.

+  `ValueGraph.lean`: Mendoza-Smith's count, and the count with each of
   its three restrictions lifted, alone and together.  Run at Mathlib
   `9f0aee2` (Lean v4.29.0-rc8, from elan) and at the pin, it gave the
   rows the report quotes; at the pin it takes about six minutes and
   7.6 GiB.
+  `Safety.lean`: whether every safe constant uses only safe ones and
   every `partial` one no `unsafe` one, as the kernel requires, with the
   safety of the `_unsafe_rec` companions; about 95 seconds and 7.4 GiB at
   the pin, where it found no violation (`../docs/lean-findings.md`,
   LF-3).
